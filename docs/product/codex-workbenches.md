# Codex workbenches

Product authority remains in the App contracts and `docs/product/gui/team-bot-and-superagent.md`.

Collaboration and Superagent use the official DSH Web application in separate profiles. Both borrow the one persistent Codex App Server through `opl-codex-agents`; neither starts another server or requires a second model-provider account. Superagent keeps its own session persistence, execution bindings, Sources, Policy, Tickets and settings. Its repository account and execution-directory setup remain explicit operator configuration in the original management UI. The profile opens the official Superagent overview through the native layout service and omits the separate model-provider onboarding plugin. Its Codex threads project the upstream account environment per thread; ordinary App threads keep their own environment.

DSH bundles load peer services dynamically. The production dependency closure, package cohort and packaged-byte validation include those peers. A successful checkout test does not replace cold startup from the built App.

Sidebar defaults come from the App build policy. Explicit choices are saved in the carrier's local preferences and take priority over defaults. Registered slots determine which entries exist. Empty overflow is hidden while unpin controls remain available; the narrow upstream compatibility patch records the missing extension point and its removal condition.

After a local Host disconnects, its failure is saved in a bounded, redacted local diagnostic. The next request creates a new Host. An interrupted mutation is never replayed automatically.
